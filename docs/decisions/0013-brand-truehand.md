# ADR-0013: The product is named Truehand; the mark is a braille cell that is also a breadboard

Status: accepted, 2026-10-25

## Context

The working name was Plumbline, after the plumb line, a reference you trust because it hangs true.
The team chose a public brand that says what the product protects: the hand that measures without
looking. Logo files were supplied by the team (now in `apps/web/public/brand/`).

## Decision

- **Name:** Truehand. Domain truehand.tech. Support and partnership email: support@truehand.tech
  (replaces hello@tryplumbline.tech).
- **The idea behind the mark:** a braille cell and a breadboard are the same shape. Both are grids
  of dots, read by fingertip, where every hole feels identical to the one beside it. The mark is a
  six-dot cell (two columns of three) with one dot filled and ringed in red: the hole the probe
  actually found. It is the product's claim drawn as a glyph: in a grid where every hole feels the
  same, Truehand works out which one you are touching.
- **Mark colours** come from the logo files: found dot #C0271D on light, #E8503F on dark, outline
  dots in ink. Token `--brand` (tokens.json) exists only for the mark. It is never a UI state
  colour; placement warnings keep `--warning`, which always comes with the left rule, the glyph and
  the word, so the two reds are never the only cue for anything.
- **Wordmark on the site** is live text in Fraunces 600 beside the inline SVG mark, so it follows
  the theme and stays crisp. The supplied logo SVGs set the wordmark in Inter (with Helvetica,
  Arial fallbacks); they are kept as the press-kit files. Inter as brand type is on the
  POSITIONING 4.3 banned list for the site, so a Fraunces version of the lockup is a follow-up for
  the team.
- **Landing motif:** the edge plumb line becomes the edge cell column: a vertical column of
  identical holes at the right page edge, with the ringed dot sliding to the hole that matches the
  reader's place on the page and settling as the page's belief converges. Hook names in
  UI_CONTRACT 5.3 are unchanged (`data-motion="plumb"`, `data-motion-string` = the column,
  `data-motion-bob` = the ringed dot).

## What changed and what did not

Renamed (amended the same day at the user's request: "edit even folder name if there is plumbline"):
every user-facing string; every doc outside `docs/brief/`; the Python packages
(`engine/plumbline` is now `engine/truehand`, `engine/plumbline_api` is now `engine/truehand_api`, project name
`truehand`); the skill folder `truehand-engine` and the rule `00-truehand.md`; the brief files
(`docs/brief/TRUEHAND_BUILD.md`, `Truehand_Scale_and_Build.md`, `Truehand_Build_Brief.pdf`,
`Truehand_Idea_and_Winning_Case.pdf`; their contents stay as written); environment variables
`TRUEHAND_*`; `localStorage` keys `truehand.*` (saved display preferences reset once); the test
hooks `window.__truehandScene` and `window.__truehandFakeRecognition`; function and type names.
Parity fixtures and `docs/results/` were regenerated under the new module name; the numbers are
identical (fixtures checked field by field; results diffed after the re-run).

Kept on purpose:

- The live Render service names and URLs (`plumbline-api`, `plumbline-web`,
  `plumbline-api.onrender.com`). Renaming a service in `render.yaml` makes Render create a new
  service; renaming happens in the Render dashboard (and the custom domain truehand.tech), then
  `render.yaml` and `VITE_API_URL` follow.
- The API also reads the legacy `PLUMBLINE_CORS_ORIGINS` as a fallback until the Render blueprint
  is re-synced (the new `TRUEHAND_CORS_ORIGINS` wins when both are set).
- `PlumbLine` components in the scene and the simulator: they draw a physical plumb line, not
  the brand.
- The external design canvas names "Plumbline UI Directions" and "Plumbline UI Mockups".
- The repository root folder is renamed last, after the running UI lanes merge (their worktrees
  live inside it).

## Amendment: deploy alias (2026-10-25)

The Render services were created in the dashboard, so `render.yaml` does not control them. The API's dashboard start command still reads `uvicorn plumbline_api.main:app`; a two-file alias package `engine/plumbline_api/` forwards to `truehand_api` so deploys work. Delete it once the dashboard start command reads `truehand_api.main:app`. The static site has no rewrite rule; the build copies `index.html` into each route folder (`apps/web/spaRoutes.ts`).
