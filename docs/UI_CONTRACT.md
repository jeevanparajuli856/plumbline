# UI contract for parallel Sprint 1 lanes

Status: v1, 2026-10-25, written on `main` before the Sprint 1 lanes launched. Owner: the integration step on `main`. Lanes build to this; changes go through `main`.

Why: `e2e` writes specs while `web-shell`, `scene`, `landing` and `voice` build the UI in parallel. Specs select by role and accessible name first, `data-testid` second. Every name below is a contract; the visible copy around it may change.

## 3. Scene (scene)

- Mounting: `SceneHost` (scene lane) renders the one Canvas. In `sceneMode === 'landing'` it is a fixed full-viewport layer behind the landing content (`pointer-events: none` except while a section asks for interaction). In `sceneMode === 'sim'` it portals into `document.getElementById('scene-slot')`, an empty element the web-shell `/sim` layout renders where the 3D panel goes; if the slot is absent (text-only view), nothing mounts.
- The scene calls `setSceneMounted(true)` from `@/state/session` on Canvas mount and `false` on unmount. Without it the store does not wait for a reveal animation; with it the store still finishes the reveal itself after `REVEAL_TIMEOUT_MS` (3000) if the scene never calls `finishReveal(token)`.
- Landing camera: `poseAt(progress)` and `ScenePose` from `@/landing/choreography` (signature frozen on `main`; landing owns the body, scene consumes the type).

- Canvas wrapper `data-testid="scene"`. In sim mode it carries `role="img"` with an `aria-label`. In landing mode the fixed layer is decorative and `aria-hidden="true"` (the landing captions are the content), so it adds no landmark and no axe `region` finding.
- `window.__truehandScene` is set in dev and test builds only to `{ drawCalls: number, frames: number }`, updated after each rendered frame, so e2e and perf can read `renderer.info.render.calls` without a GPU profiler.
- No informational text is only in the scene.
- Without WebGL (or in text-only view) no `<canvas>` is created: `SceneHost` renders `SceneUnavailable` (or nothing) and three.js is never loaded.

## 4. Voice (voice)

- `apps/web/src/voice/index.ts` exports `useVoice(): { supported: boolean, listening: boolean, toggleListen(): void, speakingEnabled: boolean }` and `startVoice(): () => void` (subscribes to the store and the announcer text, speaks only when `usePrefs.voiceEnabled` is true).
- Recognition stub for Playwright: `window.__truehandFakeRecognition = { say(transcript: string, alternatives?: string[]): void }`, installed when `?fakeVoice=1` is present (dev and test builds).
- The integration step wires `useVoice` into the `/sim` header and `M` key; until then web-shell renders the Listen button only when `useVoice` exists (it does not import voice/ during Sprint 1 lanes).

## 5. Engine (engine)

Recorded fixtures must parse with `Fixture` in `apps/web/src/engine/schemas.ts` (the web Zod mirror). In particular: `prior_instruction.gain_bits` and `steps[].engine_choice.gain_bits` are per-site arrays; `catalog.hypothesis_labels` is present; `diagnosis` is `{hypothesis_id, confidence}` or null; `landed_site` is an int or null; `placement_audit` is a list of per-site arrays.

### 5.3 Motion hooks (landing-revamp renders them, motion lane animates them)

The motion module (`landing/motion/**`) selects only by these attributes, never by class. The static DOM always renders the FINAL state; motion tweens from an earlier state to it and reverts on unmount. Under reduced motion (OS setting or `html[data-reduce-motion]`) nothing tweens and the final state stays.

| Hook                     | Element                                                                                                                                                                                                | Data the landing provides                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-motion="headline"` | the H1                                                                                                                                                                                                 | plain text only. The motion splitter wraps words at runtime (and sets `aria-label` on the H1 with the full text, `aria-hidden` on the word spans), and restores the original text on revert. The landing reserves the line height so splitting causes no layout shift                                                                                                         |
| `data-motion="quote"`    | each research quote element (`blockquote` or `p`)                                                                                                                                                      | plain text; revealed line by line once on enter                                                                                                                                                                                                                                                                                                                               |
| `data-motion="bars"`     | the technology race container (`section#play`)                                                                                                                                                         | children `data-motion-bar="published"` and `data-motion-bar="ours"`, each an element drawn with `transform: scaleX(final)` from the left, with `data-motion-stages="p0,p1,p2"`: the top-fault probability (0 to 1) before any reading, after reading 1, after reading 2, from worked_example.json. Optional `data-motion-stage-label` children are swapped by the scrub       |
| `data-motion="rows"`     | the product list (`ul` or `ol`)                                                                                                                                                                        | its direct `li` children stagger in from the left                                                                                                                                                                                                                                                                                                                             |
| `data-motion="stat"`     | the visible number in a validation stat cell, `aria-hidden="true"` next to an `sr-only` twin with the same text                                                                                        | `data-motion-value` (number), `data-motion-decimals` (int), optional `data-motion-suffix`. Counts up once from 0. The pending cell carries no hook                                                                                                                                                                                                                            |
| `data-motion="plumb"`    | the fixed edge cell column at the right page edge (`aria-hidden="true"`; was the edge plumb line, ADR-0013): a vertical column of identical hollow holes, read as the Truehand mark turned on its side | child `data-motion-string` (the column of holes) and `data-motion-bob` (the ringed, filled dot in `--brand`), which slides along the column with page scroll and wobbles between neighbouring holes with an amplitude that falls as `useLanding.progress` rises (the reading settles). Its caption twin is a visible `data-testid="caption"` in the page, not inside the hook |

Photos: `<img>` from `PHOTOS` in `landing/photos.ts` with its `alt`, `width`, `height`, `srcSet`, `loading="lazy"`, `decoding="async"`, inside a `figure` whose `figcaption` carries the credit (not a `data-testid="caption"`; those stay the scene twins). Never in `section#hero` on Home.

Status lines under the hero lead and the hero card's own animations (probe travel, digit tick, bar settle, warning strike) belong to the landing lane and use CSS transitions on the motion tokens, so they snap when the tokens are zero.
